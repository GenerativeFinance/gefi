Below is a practical, production-minded set of solutions and an implementation plan you can adopt right away to create visually appealing PDF presentations and custom PDF exports driven by user parameters (the “Create Custom Report” UI in Image 3). I include architecture options, recommended libraries/tools, a param-driven API contract, UX tips, and ready-to-drop-in sample code (server + HTML template + client helper) that uses a proven approach: render an HTML/CSS report (brandable, slide-like or multi-page) and convert it to PDF via headless Chromium (Puppeteer). This approach preserves styling, SVG/chart fidelity and gives full control of layout.

Summary recommendations (quick)
- Best quality + flexibility: Server-side render of an HTML report using headless Chromium (Puppeteer / Playwright) → PDF. Use CSS print media queries and SVG/PNG chart images for crisp output.
- Highly scalable / serverless: Use Playwright or chrome-aws-lambda in serverless functions, or run a containerized worker pool (recommended for heavy loads).
- Fast client-side downloads (for small/simple exports / instant preview): html2canvas + jsPDF or the charting library's built-in dataURI exports. Use only for simple single-page exports (limited fidelity).
- For slide-like presentations: compose HTML slides (Reveal.js, DeckDeckGo) and render to PDF (print-to-PDF) server-side.

Key features your solution must support
- Custom parameters mapping (Report Name, Date Range, Visuals, Metrics, Make Public, Schedule)
- Dynamic chart embedding (SVG or PNG) for ApexCharts/Plotly/Highcharts
- LLM-generated executive summary + notes (optional): call LLM server-side and embed the text in the PDF
- Multi-page templates: cover, TOC, executive summary, charts, tables, appendix
- Storage, scheduled generation & distribution (S3 + job queue + email)
- Preview flow: HTML preview in-app before final produce PDF
- Theming & branding: CSS variables for colors, fonts and logo

Architecture patterns (two recommended)

1) Server-side HTML render (recommended for production fidelity)
- Flow:
  1. Client calls POST /api/reports/generate with parameters (templateId, dataQuery, visuals, dateRange, schedule, recipients).
  2. Backend composes the dataset (DB queries / API pulls).
  3. Server renders a React/Handlebars/HTM L template (in-memory or via a temporary URL with a rendered page for the report).
  4. Use Puppeteer / Playwright to navigate to the rendered page and printToPDF (print media CSS).
  5. Upload PDF to S3 / GCS and store report metadata in DB; send email notifications or return signed download URL.
- Pros: pixel-perfect output, consistent styling, full CSS power, easy to include fonts and images.
- Recommended tools: Node + Express/Next API / Nest; Puppeteer or Playwright; S3; BullMQ + Redis for background jobs; EJS/Handlebars or server-side React for templates.

2) Client-side generation (for small/instant exports / preview)
- Flow:
  1. Create HTML preview in app with identical CSS.
  2. Use ApexCharts/Plotly export methods to produce base64 images of charts.
  3. Use html2canvas + jsPDF or svg2pdf + pdf-lib to build a PDF client-side and download.
- Pros: instant, no server cost.
- Cons: limited fidelity for complex layouts and long multipage reports; performance issues for large exports.

Design & UX guidelines for visually appealing reports
- Cover page: title, date range, author, logo, key summary metric card (weighted ESG score / Portfolio AUM).
- TOC page (auto-generated).
- Executive summary: short LLM-produced bullet points, 3–5 highlights.
- Visual pages: one major visualization per page for clarity (map, sunburst, heatmap, time series).
- Tables and appendices: compact tables with pagination.
- Use print CSS (page-break-before/after, avoid breaking charts).
- Footers: page numbers, generated timestamp, confidentiality disclaimer.
- Provide “visual theme” presets: executive (clean + whitespace), analyst (densely packed), ESG (green tones).

API contract (recommended)
- POST /api/reports/generate
  - Body (JSON):
    - templateId: string
    - reportName: string
    - description?: string
    - dateRange: { start: ISODate, end: ISODate }
    - metrics: [string]
    - visualizations: [{ id, type, config }]
    - layout: 'slide' | 'report'
    - recipients?: [email]
    - makePublic?: boolean
    - schedule?: { cron: string, timezone: string } (optional)
    - preview?: boolean (if true, return HTML URL or small PDF for preview)
- Returns:
  - { jobId, status, previewUrl?, pdfUrl? }
- Additional endpoints:
  - GET /api/reports/:id/status
  - GET /api/reports/:id/download (auth, signed S3 link)
  - GET /api/reports/templates (list available report templates)

Storage, scaling & scheduling
- Storage: S3 + CloudFront for distribution (signed URLs)
- Jobs: use a queue (BullMQ with Redis) to generate PDFs asynchronously
- Workers: containerized worker(s) running Puppeteer/Playwright; autoscale depending on queue depth
- Scheduled reports: schedule tasks with cron (via BullMQ repeatable jobs or external scheduler)
- Keep failure-safe: retry with exponential backoff, and store last-failed reason on report DB record

Security & compliance
- Validate user data & params before generating
- Run headless Chromium in isolated container; limit network access if possible
- Strip PII or allow inclusion only if user consents
- Use signed URLs and short TTL when distributing PDFs
- For scheduled reports with recipients, require tenant-level consent & encryption at rest

File: server/src/workers/reportGenerator.ts
```typescript name=server/src/workers/reportGenerator.ts
import puppeteer from 'puppeteer';
import fs from 'fs/promises';
import path from 'path';
import { uploadToS3 } from '../utils/storage'; // implement per your infra
import { getReportDataById, updateReportStatus } from '../db/reports'; // your DB helpers
import Mustache from 'mustache';

interface JobPayload {
  reportId: string;
  templateId: string;
  data: any; // resolved dataset and pre-rendered chart images (base64)
  options: {
    layout?: 'report' | 'slide';
    pageSize?: 'A4' | 'Letter';
    margin?: { top: string; right: string; bottom: string; left: string };
  };
}

export async function processReportJob(job: JobPayload) {
  const { reportId, templateId, data, options } = job;
  try {
    await updateReportStatus(reportId, { status: 'rendering' });

    // Load HTML template (can be a React SSR route too — here we use Mustache)
    const templatePath = path.join(__dirname, '..', 'templates', `${templateId}.html`);
    const templateHtml = await fs.readFile(templatePath, 'utf8');

    // Render template with data (data should include base64 chart images to embed)
    const renderedHtml = Mustache.render(templateHtml, data);

    // Save temp HTML file
    const tmpHtmlPath = path.join('/tmp', `${reportId}.html`);
    await fs.writeFile(tmpHtmlPath, renderedHtml, 'utf8');

    // Launch Puppeteer
    const browser = await puppeteer.launch({
      args: ['--no-sandbox', '--disable-setuid-sandbox'],
    });
    const page = await browser.newPage();

    // Set content and wait for charts / images to load
    await page.goto(`file://${tmpHtmlPath}`, { waitUntil: 'networkidle0', timeout: 60000 });

    // Optional: emulate print CSS or set background graphics
    const pdfBuffer = await page.pdf({
      format: options.pageSize || 'A4',
      printBackground: true,
      margin: options.margin || { top: '20mm', right: '12mm', bottom: '20mm', left: '12mm' },
    });

    await browser.close();

    // Upload PDF to S3 (or equivalent)
    const s3Key = `reports/${reportId}.pdf`;
    const pdfUrl = await uploadToS3(pdfBuffer, s3Key, 'application/pdf');

    // Update DB record
    await updateReportStatus(reportId, { status: 'completed', pdfUrl, completedAt: new Date().toISOString() });

    return { success: true, pdfUrl };
  } catch (err) {
    console.error('Report generation failed:', err);
    await updateReportStatus(reportId, { status: 'failed', error: String(err) });
    return { success: false, error: String(err) };
  }
}
```

// Example: collect chart images (ApexCharts) and call generate API
import axios from 'axios';

export async function exportChartImage(chartRef: any) {
  // For ApexCharts: chartRef.chart.dataURI() returns { imgURI, blob } depending on lib
  if (!chartRef?.chart) return null;
  try {
    const result = await chartRef.chart.dataURI(); // returns { imgURI }
    return result?.imgURI || null;
  } catch (err) {
    console.warn('chart export failed', err);
    return null;
  }
}

export async function generateReportApi(payload: any) {
  // payload contains pre-rendered charts as dataURI and other params
  const resp = await axios.post('/api/reports/generate', payload);
  return resp.data;
}
