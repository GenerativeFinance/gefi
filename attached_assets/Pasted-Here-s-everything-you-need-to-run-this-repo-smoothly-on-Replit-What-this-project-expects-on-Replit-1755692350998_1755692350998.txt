Here’s everything you need to run this repo smoothly on Replit.

What this project expects on Replit
- Single Node.js process serves both API and client in development using Vite middleware.
- The server binds to 0.0.0.0:5000 (hardcoded). This is intentional for Replit: port 5000 is allowed and not firewalled.
- In development (NODE_ENV=development), the server mounts Vite middleware and serves the client directly from client/index.html with HMR.

One-time setup (Replit)
- Create a new Repl: Node.js environment (Node 18+ recommended).
- Set Replit “Secrets” (Environment Variables), as needed:
  - NODE_ENV=development
  - ALLOW_DEMO_SUBS=true (enables demo subscription flows if you’re not using full auth)
  - Optional integrations (only if you use these features):
    - STRIPE_API_KEY=sk_test_... and STRIPE_WEBHOOK_SECRET=whsec_... (for real checkout)
    - MEILI_HOST=http://127.0.0.1:7700 and MEILI_MASTER_KEY=... (if you enable search services)
    - REDIS_URL=redis://localhost:6379 (if you start Redis locally for any optional queues)
- Install dependencies at the repo root:
  - npm install
  - If TypeScript runners aren’t present, add dev deps: npm i -D tsx typescript @types/node

Replit Run command (what to put in the “Run” button)
- Use tsx to run the TypeScript server directly in dev mode, which automatically serves both API and client with Vite:
  - Run command: NODE_ENV=development npx tsx server/index.ts
- The server will log “serving on port 5000” and your Replit public URL will proxy to that.

How the dev server works here
- server/index.ts
  - In development (NODE_ENV=development), it calls setupVite(app, server) from server/vite.ts, which:
    - Mounts Vite middlewares with HMR.
    - Serves client/index.html and loads /src/main.tsx with a cache-busting querystring.
  - In production, it would call serveStatic(app) which expects a static build at server/public. For Replit, stick to development unless you customize the static path (see Production note below).
  - The server always listens on port 5000 and interface 0.0.0.0.

Client build config (FYI)
- vite.config.ts is rooted at client/, and builds to dist/public at the repo root:
  - root: client
  - build outDir: dist/public (repo root)

Testing the app in Replit
- After Run starts:
  - Open the web view; you should see the app.
  - Try visiting paths like:
    - /marketplace
    - /ai-models
    - /portfolio
    - /wallet-management
- Subscriptions (demo flow):
  - If you see 401 Unauthorized when subscribing, ensure:
    - Client fetch includes credentials (this repo’s apiRequest helper is method-first and should set credentials: 'include').
    - ALLOW_DEMO_SUBS=true in Replit Secrets to allow local demo activation without full auth.

Optional services you can ignore unless needed
- Stripe checkout: requires STRIPE_API_KEY/STRIPE_WEBHOOK_SECRET and server routes that return a checkoutUrl. Without Stripe, server falls back to demo behavior when enabled.
- MeiliSearch: only needed if you enable search endpoints; otherwise leave unset.
- Redis: only needed for background queues (e.g., report generation in some attached patches).

Production build note (if you ever want to run NODE_ENV=production on Replit)
- By default, serveStatic(app) looks for server/public, but vite build outputs to dist/public.
- If you really need to run production locally, run:
  - npx vite build
  - Then either:
    - Copy or symlink the build to server/public:
      - mkdir -p server && rm -rf server/public && mkdir -p server/public && cp -r dist/public/* server/public/
      - Or: ln -s ../dist/public server/public
    - Start with NODE_ENV=production (you’d also need to transpile server TS to JS or use tsx in production, which is not typical).
- Recommendation: stay in development mode on Replit for the intended flow.

Quick troubleshooting
- If the client doesn’t load: confirm the Run command uses NODE_ENV=development and port 5000; verify logs show setupVite mounted and “serving on port 5000”.
- If HMR warnings appear: safe to ignore; they’re from Vite’s dev websocket during startup.
- If subscribe still throws 401: ensure your session is present, credentials: 'include' on fetch, and ALLOW_DEMO_SUBS=true if testing without auth.
