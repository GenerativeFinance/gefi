Stale state bug: securityAttempts checked immediately after setSecurityAttempts
Severity: High (can allow unlimited retries or incorrectly fail on first wrong attempt).
Cause: You call setSecurityAttempts(prev => prev + 1) then check securityAttempts (stale closure).
Fix: Read the incremented value (use functional result or derive local variable) before branching.
Captcha regeneration & randomness
Severity: Medium
Cause: If generateCaptcha isn't called on each security step or after failure, user can get same captcha repeatedly.
Fix: Call setCaptcha(generateCaptcha()) whenever the security step opens and after failures. Use a sufficiently random generator; avoid trivial deterministic math always returning "2 + 2".
Creating pending account immediately vs. email verification
Severity: Medium
Cause: You create pending account in security branch but in the else branch you require email verification before creating the account. Decide consistent flow:
If security step passed, create account as pending.
If email verification required, create pending account after verification or create pending now and set verification flag.
Recommendation: Create a pending account once (with status pending) and then verify email server-side; reduce duplicated flows.
Exposing verification code in chat
Severity: High (security/privacy)
Cause: addBotMessage(For demo purposes, your verification code is: ${data.verificationCode});
Fix: Remove that in production; only enable via a dev flag or DEBUG environment variable.
recaptchaToken / honeypot / sessionId handling
